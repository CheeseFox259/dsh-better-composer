# 装饰按草稿行而非宿主 DOM 段落，块级原子生效

Composer 装饰管线收拢为 `src/decoration/`（装饰投影）时确立：装饰的基本单位是**草稿行**（按 `\n` 划分），而不是宿主 Lexical 的段落元素；同一块内各行签名一致才整块装饰，否则整块回退原生显示（**块级原子装饰**）。

## 理由

- 插件不控制换行产生的 DOM 形状：粘贴经 `setDraft` 重建为一行一个 `<p>`，手打 Shift+Enter 在同一个 `<p>` 内插 `<br>`。旧实现把块级装饰挂在 `<p>.classList` 上，隐含「一行=一个 `<p>`」假设，导致手打列表不渲染、换行波及上文缩进。
- CSS Custom Highlight API 的 `::highlight()` 只支持绘制类属性，无法做布局（缩进）；同 `<p>` 内按行缩进在 CSS 层无解，因此混杂块只能整体回退，不允许「marker 已隐藏但布局装饰缺失」的半成品状态。
- 块冲突判定依赖 DOM 形状，只能发生在 install 侧；纯函数 `project()` 只产出按行的签名与声明式计划，不感知 DOM。

## Consequences

- 同一 `<p>` 内 `<br>` 分隔的同深度列表可完整装饰（手打/粘贴视觉一致）；普通文字与列表混排的块整体回退原生显示。
- 未来评审若提出「块内按行部分装饰」，先读本 ADR；仅当宿主提供行级布局能力（或插件接管换行使每行独立成段）时方可重开。
