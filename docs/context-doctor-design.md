# Context Doctor：产品设计基线

版本：v1.0 / 设计定稿。
状态：仅设计，未开发。本文是 Context Doctor 的产品基线；确认项、能力边界与开发前提已收敛。任何实现须等待用户明确发出开发指令。

## 1. 定位与成功标准（用户已确认）

Context Doctor 是现有上下文地图的质量诊断与优化辅助功能。

- **会话视角**：按照 DSH 真实的上下文及消息结构，量化组成、组织、使用和保留方面的问题，给出证据与 DSH 可执行或可手工处理的建议。
- **模式视角**：评价 Agent 预设自身的质量——是否完整、精简、一致地实现模式自己的目标。允许读取使用同一模式的所有可访问会话，以统计与用户反馈支撑分析，不做“是否适合当前聊天”的模式推荐。
- **核心价值顺序**：质量和任务状态清晰；利用 DSH 能力改善组织；节省不必要的上下文负担。
- **量化展示本身就是价值**，不只是生成一段诊断报告的中间步骤。
- **首版成功**：正确定位问题，有可追溯证据，提供符合 DSH 能力的可操作建议。不要求证明下游质量提升，不建 A/B 回放平台。

优先用采集数据与确定性逻辑计算；必要的语义分析由用户主动要求后调用模型。用户确认的优化操作与只读诊断严格分开。

**需求与可实现性分开**：模式目标评价是用户需求，不是已经实现的能力。compositionInventory本身仅有名册；第三轮补核找到公开standingMountFor/livePresetMounts及树读取路径，可取得当前活跃代际配置（architecture §11）。冷历史完整版本仍unknown，未加载Skill源或无法确定的动态配置仍须coverage。拿到配置也不等于自动证明自然语言目标已覆盖，需声明目标/能力映射及必要人工或显式语义分析。保留该需求，不以缺数据擅自删减，不宣称完整运行验证已完成。

## 2. 已确认需求清单

| ID | 用户要求 | 后续产物 / 验收重点 |
|---|---|---|
| R-01 | 按不同结构采用不同质量标准，不只看长度 | metrics：对象、用途与归属；experience：分结构下钻 |
| R-02 | 系统 Prompt 优先放高复用、高必要性、低变化内容，允许必要例外 | 指标显示变化和负担，不能未经语义依据断言位置错误 |
| R-03 | 当前任务自动推断、可由用户纠正 | 可选语义分析流程，不暗中每轮调用模型 |
| R-04 | 工具定义、执行生命周期、相似工具混淆与误用都应考虑 | 曝光/调用/错误及混淆候选契约；结果仍可不确定 |
| R-05 | Skill、插件、MCP 使用数据与冗余也是分析对象 | 不同贡献类型分别计量，低频不等于无用 |
| R-06 | 模式分析独立于当前会话，检查自身目标、能力覆盖和预设质量 | 配置来源与群体数据分别呈现，替代能力不误判缺口 |
| R-07 | 可读取同一模式的全部 session | 只读、有界历史读取；模式 ID/版本/样本覆盖明确 |
| R-08 | 重复困扰、追加工作、返工由用户方便反馈并提供证据 | 低步骤反馈、关联同一问题、证据链；不默认 LLM 扫描历史 |
| R-09 | 按上下文占比加权判断影响程度 | 加权算例与反例；不能混同资源负担与语义危害 |
| R-10 | 将量化数据展示给用户 | 会话/模式两个范围、表格图表、覆盖状态、证据下钻 |
| R-11 | 增强有效要求、纠偏结论和流程约束，使长上下文和压缩后不易丢失 | 来源不限单条用户命令；确认原文、提炼、条件和差异；具体机制待设计 |
| R-12 | 不干预 Agent 遗漏行为，尽量少用大模型 | 不监控完成、不催促、不自动续写、不运行自动验收 |
| R-13 | 当前未发送草稿不纳入首版诊断 | 不采集 draft 作为诊断对象；候选输出动作另行明确 |
| R-14 | 模式/约束诊断主动点击，模型授权可持续 | 采集/统计与语义诊断分离；持续授权不是自动执行 |
| R-15 | 分析模型默认跟随会话，可独立选择宿主已有模型 | 不引入独立账号；范围、预算、取消和失败路径待第二轮 |
| R-16 | 只用公开支持的接口，插件独立安装 | 不改宿主，不用私有状态，不为完整性编造来源 |
| R-17 | 操作属于用户审阅确认后的辅助执行 | 诊断、生成候选、采用、执行分别可见 |

“已确认需求”不意味着相关实现能力已证明。无法实现的部分必须提交降级/延期决策，不能悄悄缩减。

## 3. 第一轮产物 grill 决策与方案

### 第一轮已确认（2026-09-25）

- G1=A：界面默认估算 token，明确标记估算；供应商观测总量独立展示，底层保留文本体积，不用缩放伪造精确分项。
- G2：采用资源贡献占比加权与独立质量问题并列；不以体积压低关键要求或用户返工问题的重要性。
- G3=A：保留同模式历史分析价值，未知版本不伪归当前版本。排除过短会话；用户以少于4轮为例，设计暂采用4轮为最低门槛，具体轮次口径待第二轮确认。归档会话也纳入，必须考虑时效性。
- G4=B：允许轻量被动采集公开接口可得的必要指纹和变更；不调用模型、不执行工具、不主动探测MCP，不判断任务完成。
- 第一轮未确认的细节以下方第二轮决策为准，不将推荐等同用户确认。

### 第二轮已确认及纠偏（2026-09-25）

- H1：时效由相关配置/内容版本决定，上下文和模式均如此。同版本样本不因日期或归档失效；撤销默认最近30天方案。历史未知版本不能假作相同版本。
- H2=A：至少四条有效交替消息，即两个完整用户—模型往返 `U1 → A1 → U2 → A2`，不是四个往返或四个运行turn。中断/取消须看原因；后续只说继续而没有新指令时归并恢复链，不靠重试凑门槛。
- H3：同意地图内当前会话/模式预设两个视角及独立模式选择。
- H4：接受轻量反馈与关联已有问题流程。
- H5：基本认可增强影响后续上下文，但压缩后已经保留的要求不能重复注入；优先在compact过程中保留并去重。具体公共扩展能力待核查，不承诺默认额外LLM语义评审或每次补发。
- 完整模式配置来源、版本依赖字段、指标范围、compact的缺失/不确定处理以及预算等尚未定稿。

### 第三轮已确认（2026-09-25）

- J1接受：compact保护作为按模式显式启用的可选provider，不安装即接管；这是设计取舍确认，不是现在修改用户模式的授权。
- J2=A：fork只计算本分支自己的有效往返，继承历史不用于使短分支达标。
- J3：无法确定属于纯恢复的消息按正常对话处理，不合并为恢复；仍需有效模型回应才形成完整往返，日志缺失不因此忽略。
- J4=B：反馈选中的证据随源会话删除，只保留问题类型及用户自填说明等非原文记录；归档不算删除。具体删除核实/缓存清理见架构§14.3。
- J5采用：手动语义分析默认最多2次调用，总输入约24k tokens，每次输出最多4k且服从模型限制；超范围先缩证据或用户显式扩额。compact预算独立。
- J6最终决定：约束保护只执行，不校验；取消保留结果校验、校验失败拦截、额外judge及保护效果重试。在同一次compact任务中靠去重的输入组织、保留指令与正常宿主能力完成增强，不在输出后反复证明效果。一般软件错误处理和开发测试保留，不成为日常使用负担。
- 产品设计准则：优先把能力做进插件，避免以无止境验证和确认替代能力。此准则不取消量化证据和正常操作权限，也不授权现在开始开发。剩余仅整体设计确认。

### 3.1 数据与指标

以宿主侧有界只读历史处理为主要分析路径，前端呈现摘要与按需证据。当前地图的 live 投影保留其显示职责，不直接当成全部历史指标的数据源。

- 事件轨迹、宿主有效表面、重建的宿主请求、供应商序列化请求分开。
- 供应商 usage 是观测总量；组件占用是同口径的重建尺寸或模型特定估计，不强行分摊 usage。
- 角色、用途、组件来源分别作为维度，避免 Skill 正文经工具结果返回时被重复统计。
- Native、PTC、MCP、Skill 手势等真实路径单独处理，不用“调用率”概括所有组件。
- 重复、未使用、失败等测量与质量解释分开。近重复与工具混淆默认属于候选，不直接生成删除结论。

详见 `context-doctor/metrics.md`；数据核查证据见 `context-doctor/architecture.md`。

### 3.2 影响加权

首轮推荐：同一问题类别内用“组件占比 × 组件内问题涉及比例”解释该问题的整体资源影响；关键约束、结构问题和用户反馈单独展示重要性，不按 token 少而掩盖。不预设一个所有维度混加的万能健康分。

当前占用、跨请求累计携带、典型会话与总资源负担分别呈现。详细公式、缺失处理和算例见 metrics 文档。

### 3.3 模式统计

区分模式当前配置、历史模式 ID、观测到的能力/内容指纹和真正的配置版本。历史缺失版本不补造；允许按模式 ID 聚合，但明确为版本混合样本，不能用于严格改版归因。

所有可访问会话为可分析全集；读取中显示覆盖并可取消，不通过激活冷 Agent 的订阅方式拉取全量历史。

### 3.4 产品闭环

查看量化 → 定位来源 → 判断是否值得处理 → 生成/阅读建议 → 用户确认采用。

用户反馈是独立结果证据。约束增强的两条核心场景仍在设计范围：
1. Agent 错误理解被纠正，后续不应回到旧理解。
2. 开发交付反复遗漏测试环境与人工验收准备，提炼并保护已成立的流程要求。

不把这两条场景改造成运行时监工，不把保存一个文件当成增强已生效。

## 4. 明确不做

- 不自动判断任务完成并强迫 Agent 补做。
- 不把模式评估做成当前任务的模式推荐。
- 不让 LLM 扫描同模式所有会话归因返工。
- 不把 fork 当作受控实验或默认引入回放平台。
- 不修改历史、不将用户要求隐式提升成 system 权限。
- 不将低调用率直接解释为无价值或删除依据。
- 不为诊断自动执行外部工具、启动 MCP 探测或付费模型调用。
- 不把一般安全扫描、商业化、团队协作或 CI 平台塞入首版。

## 5. 已撤销的旧草案判断

| 旧判断 | 当前处理 |
|---|---|
| 固定九个检测器、固定占用阈值 | 撤销，按指标契约及真实可得数据设计 |
| 全量历史或最后压缩之后就是实际上下文 | 撤销，按表面替换和请求边界重建并声明范围 |
| projectedTokens 是实测 | 撤销，保留预测/估计标签 |
| 累计 cacheRead / 当前 projected 是缓存覆盖 | 撤销，累计与单请求不能相除成覆盖率 |
| pin 轮次保护压缩内容 | 撤销，现有 pin 是显示书签 |
| 模式是提示词模板或默认存在模式叠加 | 撤销，模式是 Agent 能力组合 |
| 首版分叉即天然 A/B | 撤销，不作质量验证承诺 |
| 自动持续语义分析或结轮纠偏 | 排除；保留手动诊断与审阅辅助 |
| SECRET 扫描为强制主流程门槛 | 非已确认需求，不作为主流程依赖 |
| 所有诊断数据仅存浏览器 localStorage | 撤销，跨会话分析需设计宿主侧边界 |
| 缺少插件自有 shim 声明即宿主私有 API | 撤销，以实际公开导出和文档核实 |

## 6. 研究输入与证据纪律

输入包括 `~/Codefield/context_docter/` 中早期四份材料，以及用户在本会话提供的 Gemini/ChatGPT 指标研究全文。它们是设计候选，不是用户访谈或本产品实测效果。

采纳：事实/代理/结果分离、指标分母、生命周期、来源和缺失状态、可解释下钻。

不直接采纳：通用危险阈值、执行时延保证、低频=冗余、无外显证据=未遵循、词汇保持=语义无损、相关性=模式因果责任。

上轮文档声称的部分“外部依据已查证”没有可复用的一手查证记录。本轮不将这些声称作为完成核验；若最终选用相应方法或引用论文，必须重新核验原始来源。当前源码核查是独立的本地证据，不以研究报告替代。

专题 3（加权）、4（模式聚合）、5（反馈）由本项目自主设计；专题 1、2、6 的研究主要提供方法候选。
