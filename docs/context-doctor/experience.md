# Context Doctor：交互、反馈与增强方案

版本 v1.0，2026-09-25。设计定稿；只设计，不实现。本文已替换基于最近30天及无条件压缩后重注入的旧方案。

## 1. 已确认与尚未确定

已确认：
- 地图内“当前会话 / 模式预设”两个视角，模式对象可以独立选择，不以当前聊天任务决定模式质量。
- 消息/工具结果上的轻量反馈，类型选择、自动附证据、可补原要求与纠正消息、可关联已有问题。
- 估算token默认展示；资源占比贡献与独立质量问题并列；归档样本参加。
- 时效由相关配置/内容版本决定，不由自然时间决定。同版本旧样本不自动过期。
- 短对话排除模式统计，要看有效用户—模型交互；纯“继续”恢复不能凑交互数量。
- 约束增强基本方向认可，但压缩时已保留的约束不能再次注入；优先在compact过程中保护。
- 轻量被动观测允许，必要语义分析手动启动，不监控Agent是否完成或遗漏工作。

H2=A已确认：最低门槛为四条有效交替消息，即 `U1 → A1 → U2 → A2` 两个完整往返，先归并纯继续恢复链。

未决：不可判恢复边界如何显示/筛选；compact公开接入可行性及不能确认语义保留时的处理；完整模式配置和版本来源。

## 2. 入口与信息架构

现有地图入口保留。顶部两个视角：当前会话、模式预设。模式默认取当前会话模式，但可切换；模式报告不因切换聊天自动变成另一对象。没有当前会话时的独立模式入口仍需核实公开槽位。

侧栏以简表和重点条目为主，展开显示完整列表。保持原地图系统/工具/消息浏览能力，不另建全局监控工作台。

## 3. 有效对话与样本筛选

### 3.1 门槛原则

H2=A：至少两个完整有效往返（四条交替消息：用户—模型—用户—模型）。不能按step、tool调用或原始turn数量计数；纯继续恢复链归并后再判断门槛。

恢复链应保留原始证据：中断原因、原用户指令、模型输出、后续输入及是否新增要求。

- 只有继续/恢复且没有新要求：合并到原交互，不增加深度。
- “继续，但不要改数据库”：包含实质新约束，不能按继续关键词合并。
- 取消后换目标或纠正原理解：作为新交互候选，而非无条件并入旧请求。
- J3已确认：原因缺失或无法确定是纯恢复时，按正常对话处理，不归并为恢复；不为计数启动历史LLM分类。仍须有实际用户输入和有效模型回应，不能把未完成或缺失回应自动算成完整往返。

资格依据归并后的完整有效往返数判断，不再因恢复语义不确定进入人工待判队列。日志缺失等数据覆盖问题仍单独标记，用户可查看并纠正归并依据。

J2=A已确认：fork只计算本分支自身的有效往返；继承对话可用于理解输入，不用于使短分支达到模式样本门槛。

### 3.2 归档与短对话反馈

归档不等于删除，无论归档多久，同一可证版本且满足交互条件的会话正常参加。

短会话仍可单独诊断和反馈；问题实例保存并显示“群体指标范围外”，不能用这些反馈的分子除筛除它们后的分母。

## 4. 证据下钻与结论有效性

路径：指标/问题 → 组件或发生实例 → 会话交互及底层事件 → 对应消息区间、配置、参数与结果。

EvidenceRef保存稳定来源、seq、块位置及内容hash，不用列表序号充当身份。源删除或变化时显示缺失/旧版本，不跳到别处。

结论记录依赖：哪些配置/内容、哪些指标规则、何种模型（若使用）、样本截止边界。只重算受变化影响的部分；无关内容变化不自动重跑全部语义分析。未知依赖范围时标待复核，不能假定结论仍有效。

保存时间仅用于审计。相同相关版本的老结论不因过30天失效；新增样本使群体统计可更新但不使旧实例失去资格。

## 5. 轻量反馈（H4已确认）

### 5.1 最小提交

从消息/工具结果点击“记录问题”，选择遗漏/理解偏差/需要补做/返工/其他后保存。自动附带选中证据、会话、modeId、已知或未知版本及时间。

原要求、纠正消息、说明为可选补充；不强迫填写根因或长表。消息旁公共slot不可用时，在地图自身消息浏览里提供，不改宿主私有UI。

```text
记录问题
证据：当前交付消息 [查看]
类型：[遗漏] [理解偏差] [补做] [返工] [其他]
关联：[新问题 / 已有问题]
说明（可选）：____________
[＋原要求] [＋纠正消息]       [保存]
```

无LLM、不发送会话消息、不改变Agent行为。

### 5.2 问题与发生实例

Problem包含多个Occurrence；每个Occurrence可有多个证据引用。再次遇到同类问题时直接选择已有Problem并附本次消息。文本/标签相似只能提示关联，不能自动把两个问题合并。

同一次发生多次提交时提示去重，允许用户确认；多标签不增加发生数，影响会话数按unique session。

occurredAt和reportedAt分开；问题归于证据发生时的版本，用户今天补录旧问题不属于新版本新实例。未知版本不按当前配置回填。

### 5.3 修改与撤回

可编辑、补证据、解除关联、撤回、合并后撤销。当前统计随反馈数据版本变化重新计算，不自动运行模型。

J4=B：归档不使证据失效；源会话确认删除后清除其证据正文与摘录缓存，只保留问题类型、用户自行填写的说明及“证据已删除”提示，不能再次提供该原文。暂时不可读不冒充删除；离线期间无法承诺即时物理清理，重新连接后优先同步，核实前不展示缓存正文。清缓存不等于撤回反馈。用户标记“已处理”只是处理状态，不是已证明模式修复。

## 6. 约束增强：优先压缩内保留

### 6.1 范围

Doctor帮助用户把有效要求、纠偏和流程要求整理为可审阅的保护对象。不监督交付、不检查端口、不启动环境、不阻止Agent结轮。

入口：从反馈链“整理为增强建议”，或选择消息范围“梳理有效要求”。原文摘录、来源绑定和手工编辑不需模型；用户选择模型梳理时才发送所选证据与必要邻近内容。

### 6.2 审阅

原文与候选并列，显示当前有效理解、适用条件、例外和来源。原错误理解留在审阅证据中，不默认再与正确要求等权注入。

候选新增例外必须标待确认；用户确认不擅自提升指令权限。复制、保存、纳入压缩保护、实际保留和模型遵循是不同状态。

### 6.3 两个场景

**理解纠偏**：用户纠正本轮只设计。候选准确保留范围和开发授权条件，不泛化成永久禁止代码开发。

**验收流程**：Agent反复遗漏测试环境，用户附原要求及提醒。候选提炼已成立的交付要求；原文未出现的跳过条件或异常处理不得默认为已授权。

### 6.4 保护只执行，不校验（用户最终决定）

流程收敛为：用户确认有效要求→插件组织已去重的保留依据与适用条件→在既有compact摘要任务中执行增强→按宿主正常事务完成。

- 在生成前整理要求集合及未压缩部分的已知表达，避免把同一ID/revision重复拼入任务；摘要指令明确保留条件/例外、融合已有表达而非生成另一份副本。
- 同一次compact模型调用完成摘要和约束保留，不新增Doctor judge调用。
- 不在摘要后逐条匹配原文、验证保留ID、判定语义等价；不产生“保护校验失败”流程，不因Doctor保留判断拒绝摘要。
- 压缩后不另发整包约束，不要求用户逐次检查摘要。依靠输入组织、版本管理、清晰摘要任务及正常宿主能力实现目标，不承诺模型一定遵循。
- 宿主原有网络/取消/内容类型/并发/缩减/持久化规则保留；操作本身失败仍正常反馈，不增加保护效果重试。

J1已确认按模式显式启用可选provider：选择目标模式→展示provider与保留配置Diff→提示旧Agent代际和无compact模式限制→用户确认。关闭/卸载恢复时仍处理用户配置冲突，不静默覆盖或重启。

### 6.5 状态与撤销

状态反映操作：候选→用户确认→增强已启用→摘要进行中→增强摘要完成/取消/操作失败。删除“已验证保留、保留校验失败”等结果状态。

撤销影响今后摘要任务，不重写过去已发送消息。明确修改确认要求时保存revision，按正常操作并发处理，不由后台模型不断审查是否仍有效。已存在要求不自动再注入；不存在或需要显式补充时由用户采用动作处理，不擅自发送。

## 7. 必要模型分析

动作区分：更新统计、会话质量分析、模式质量分析、选择性要求梳理。后三者只有用户明确启动才可能调用模型；compact保留设计不自动授权额外诊断调用。

启动前可见路由、范围、输入估算和调用/输出上限；持续授权减少重复提示，不代表自动运行。模型结果必须绑定证据和源版本，失效后待用户重跑。

状态：准备、分析中、完成、部分完成、取消、失败。展示已知块进度，不虚构百分比；取消不保证撤销已产生费用。缺完整模式配置时只允许明确范围的部分分析，不声称预设完整评估。

## 8. 更新后的验收故事

1. 一年前归档样本与今天具有相同可证版本：都可纳入，不按年龄降权。
2. 昨天V1、今天V2：版本分组，不因时间接近合并。
3. 相同modeId但版本未知：独立unknown组，不冒充V2。
4. 同版本新增样本：重算统计可增量处理，旧实例不失效。
5. 原请求三次中断，后续都只有继续：不得凑成四次有效往返。
6. “继续，但禁止改数据库”：包含新约束，不能视为纯继续。
7. 短会话反馈仍可记录；不混入筛除后的模式比率。
8. 归档原文正常可读；删除原文则证据状态明确失效。
9. 用户新增要求导致补做，不自动判先前Agent遗漏或模式缺陷。
10. compact任务含已去重的确认要求及融合指令；压缩完成后不再追加约束副本。
11. 验收要求明确在保留后缀中：在摘要输入中说明无需再列，不在输出后检查它是否重复。
12. compact结果使用同义改写：不触发Doctor保留校验、额外judge或效果重试。
13. 当前模式未启用公开扩展：显示未启用，不偷改宿主或给无压缩模式增配。
14. 全过程不启动测试环境、不自动催促Agent、不新增背景LLM调用。

## 9. 第三轮确认与设计收尾

J1接受显式可选provider；实际启用需确认目标模式和Diff，不安装即接管。
J2=A：fork仅自身两个有效往返可达标。
J3：不能确定为恢复则按正常对话，不合并，不因语义歧义排除；缺失模型回应仍不是完整往返。
J4=B：源会话删除时清除所附原文证据，仅保留类型和用户说明等记录。
J5：手动分析最多2次调用、总输入约24k tokens、每次输出最多4k，允许用户显式调整；compact使用原有独立预算。
J6最终决定：保护约束只执行，不校验。原保护失败选择题撤销，能力放在输入组织与同一次增强摘要，不另建验证流程。

设计已收敛，不再新增产品取舍或验证功能。后续只有在用户明确要求开发后，才开始编码。
