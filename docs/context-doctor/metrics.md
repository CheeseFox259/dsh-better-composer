# Context Doctor：指标契约与加权设计

版本 v1.0 / 设计定稿。指标范围、公式口径、缺失状态与加权方案已收敛；只读核查事实引用 architecture.md 的 A01–A22。没有实现代码、真实用户测量或性能测试。

## 1. 共同契约

### 1.1 数据对象

- s：会话；r：可识别模型请求/尝试；t：用户轮次；b：块实例；k：排他组件桶；g：模式样本集。
- 一个 turn 可有多 step，一 step 可有 retry；request/header 不是请求计数事件。
- 块实例 ID = 来源会话/事件 seq/内容块位置；contentHash 判断文字相等，不将两个相同实例合并成一个来源。
- 继承内容保留原来源，分叉后的新请求仍会重新携带它；原执行与后续携带分别统计。
- 每条指标附：scope、截止 seq/时间范围、metricVersion、计量方法、数据来源、numerator/denominator（比率）、覆盖、来源引用、局限。
- 全文累计与模式聚合中的请求集合统一为 `R_s = {该会话 own 区间内、满足本指标前提的可识别请求}`，即 `Σ请求` 与 `Σr` 均只遍历 R_s。继承历史可用来重建该集合中请求的输入，不能新增执行样本。
- C01/C08 的 `input-total` 明确定义为已规范化且互斥的 `uncachedInput + cacheRead + cacheWrite`，不含 output。output 独立展示，不加入任何输入占比或缓存率分母。
- T02 适用 Native API 可直调工具（包括 PTC 的 run_code 入口），不适用 PTC 内部 SDK 子工具；后者严格按 T08 的曝光条件计算。基础指推荐优先级，不代表无条件适用。
- E4 的6000 tokens是父子会话合并后的真实执行输入小计；单看子会话自身执行小计为3000。

### 1.2 观测质量与结论类型独立

观测质量：stored event / reconstructed host / provider reported / local estimate / partial / unavailable。
结论类型：直接现象 / 代理信号 / 用户或外部结果证据 / 受控因果证据。首版不建立因果实验引擎。

“精确字符串相等”可以确定，但是否冗余仍是代理；provider reported 代表提供方报告，不保证全请求或所有账单均可见。

### 1.3 尺寸与加权推荐

并存两套数值，不伪装一致：

1. **观测 token 总量**：请求所属 route 的 usage，缺失不补零。只在已知适配语义下合并 input/cache buckets。
2. **可见文本重建尺寸**：UTF-8 bytes 与字符数；对工具 schema 固定“Doctor 表示版本”序列化并标为重建表示，不称实际 wire bytes。若有适配 tokenizer 再加 token estimate。

G1 已确认：界面默认展示「估算 token」及同口径的「估算 token 占比」；供应商观测总量独立展示。可展开查看文本体积，或切换为文本体积视角；一个加权结果的分子分母必须使用同一方法和版本，不按供应商总量缩放分项。多模态提供数量、分辨率/字节等已有信息，不把 base64 长度算作 token，不把仅文本可计量分母标成全部模态总输入。

字符/4 可继续兼容宿主旧显示，但不能把该启发式标为供应商精确分项。不要用它推断中文质量较差。不同模型 token 不混成跨模型统一权重；跨模型可使用相同重建 byte 口径并独立显示 route。

### 1.4 排他归属与正交视图

每个文本区间在同一组成视图只有一个叶子桶：系统普通段、工具定义/SDK、Skill 目录、Skill 正文、一般会话文本、一般工具结果、明确参考材料、unknown。

这不是固定优先级覆盖猜测；以结构化来源优先建立区间，匹配含糊时放 unknown。Skill 正文通过 tool result 到达时，组件用途=Skill正文，消息角色=tool；MCP 身份为组件来源标签，不再加一遍。

可切换角色视图/用途视图/来源视图，但不将不同视图的总和相加。配置声明为某插件，不足以证明每一段文本都来自它。

### 1.5 缺失值

| 状态 | 何时使用 |
|---|---|
| 0 | 有有效分母/观测，计数确为零 |
| no_samples | 逻辑适用，但没有 eligible 样本或分母为零 |
| not_applicable | 机制不存在，例如当前 DSH 未支持 MCP Prompts |
| unobservable | 缺所需事件/接口，不能计算 |
| partial | 仅部分可计算，显示有效样本/全部候选与丢失原因 |
| estimated / reconstructed | 方法标记，可与 partial 并存，不用一个空值取代 |

同指标在缺数据后不自动退换一个不同公式。失败读取仍计入候选覆盖，不从报告悄悄消失。

## 3. 权重与问题解释

### 3.1 同一资源问题的贡献

在一个完整且同口径的文本组成中，组件重量 Wk、问题区间重量 Dkj：

w_k = Wk / ΣWk

d_kj = Dkj / Wk（Wk=0 时该桶贡献为0，但不显示内部比率）

I_j = Σk w_k × d_kj = Σk Dkj / Σk Wk

j 是同一问题类别，例如“额外精确副本”。同类区间重叠求并集，代表副本的选择固定可复算。不同问题 j 不直接求和，避免同一段同时近重复/再加载而双扣。

名称为“该问题涉及的输入体积占比”，不是错误概率、浪费比例或安全删除量。

### 3.2 关键性不被体积淹没

不通过 arbitrarily 给缺失约束100倍权重来混成总分。独立列出：
- 用户确认问题及其影响范围；
- 明确结构异常/必要能力不可达证据；
- 代理风险（条件及证据强度）；
- 资源负担（可加权）。

推荐列表先按用户选择的维度看，默认组内按覆盖充分性与影响范围排序，再看资源贡献。同一问题卡可同时有资源量和反馈，但不加成伪概率。跨组唯一排序公式尚不需要。

### 3.3 不完整情况

设只有60%的文本区间能归属组件：报告“已归属60%，其余unknown”。若unknown文本本身仍可做重复检测，可在unknown桶计算；若根本无正文，缺失区间的重复程度未知。

已观测部分重复率10%，不能说完整输入重复率10%。若具有同单位全量尺寸边界，可给区间下界/上界并解释；否则只给已分析子集结果，不能编造整体边界。

## 4. 模式样本与聚合

### 4.1 三个筛选层

1. **模式全集**：通过业务可见列表找到 modeId 相同的会话；用户允许全部读取，不等于当前配置版本已知。
2. **报告窗口**：用户选时间范围/模型/配置或观测指纹；默认时间窗口尚待UI阶段，全集仍可访问。
3. **每项指标有效样本**：满足曝光、请求重建、正文、usage 等各自前提的会话/请求。

每个指标显示各层数量：候选会话、可读会话、可计算会话、有效请求、未知/失败原因。不要只显示一个N掩盖各指标分母不同。

### 4.2 配置版本

- modeId 为真实ID，历史配置version未知时进入 unknown-version，不归到当前配置。
- current composition 是当前诊断对象；历史反馈可关联modeId，不声称由当前配置导致。
- observed fingerprint（模型可见的工具/Skill等）有实际值时可以分组，但它不是完整模式配置版本。
- 若以后能采集完整权威配置版本，只比较已关联到实际运行代际的样本；当前列表快照与正在运行旧Agent之间不能盲配。

### 4.3 两种聚合都展示但名字不同

会话内先计算资源问题贡献 Is = Σ请求Dj / Σ请求W。

- **典型会话**：显示 Is 的中位数、分布及必要时会话等权均值 (ΣIs)/S；适合“通常怎样”。
- **总体资源贡献**：ΣsΣrDj / ΣsΣrW；适合“总负担集中在哪里”。

比率类工具指标跨会话采用合法分子/分母聚合，不能机械平均各会话百分比；可另展示会话率分布。用户反馈按唯一会话去重，跨问题标签总计需union。

### 4.4 Fork

执行账本：只统计本会话 own 事件与attempt；继承区间不算再次执行，禁止对子会话累计usage投影直接再求和。

携带账本：子会话own请求中的继承内容照样算携带；不因为来源属于父会话而免计其新请求成本。

反馈：同一历史问题在fork前已发生一次，不因复制历史自动产生新反馈；分叉后用户报告新的发生实例可独立记录，并关联共同问题。

### 4.5 成分差异和使用机会

默认按model/调用呈现方式/可见能力切片，不能用模式A的开发任务与模式B的讨论任务直接判优劣。没有任务标签时不调用LLM给全历史打标签；保留不可比说明。

“有工具可见”是可测曝光分母，“任务确实需要工具”是另一个目前常未知的机会分母。前者覆盖低仅说明使用少，不说明多余。

## 5. 完整设计算例（虚构、非实测）

### E1：同口径资源加权

某宿主重建请求100,000 bytes：普通system 10,000；工具schema 20,000；Skill正文10,000；一般消息20,000；一般工具结果40,000。

工具结果内额外精确副本8,000 bytes，Skill正文中额外精确副本2,000 bytes。

I_duplicate = 40%×20% + 10%×20% = 10%。报告“额外精确副本10,000 bytes / 可见文本100,000 bytes”。

Skill正文原本处在tool角色中也只计10,000一次。若另一个普通消息含40 bytes的关键验收要求且已丢失，它不因体积小而被排到不重要；列入独立保留问题。

### E2：短长会话的不同结论

S1累计输入表示100,000 bytes，重复10,000（10%）；S2累计1,000,000，重复300,000（30%）。

会话等权均值20%；总体资源贡献310,000/1,100,000=28.18%。两者都正确，分别称“会话均值”和“总输入贡献”；不从一个挑选更好看的值。

### E3：缺失曝光不是零

模式共20个可读会话，15个有完整原生工具曝光记录。工具A在其中10个可见，4个发生own调用；另外5个缺曝光记录，即使其中看到调用也不能塞进上述可比率分子。

报告“已观测可见会话使用覆盖4/10=40%；曝光观测覆盖15/20=75%；另5个曝光不完整，调用次数仍可单列”。不报告4/20=20%，也不把另外5个当未用。

### E4：分叉原执行与携带

父会话2次调用，报告输入1000、2000 tokens。子会话复制这段历史，再own调用1次输入3000。按旧累计投影相加可能得到父3000 + 子6000 =9000。

Doctor实际执行小计应为6000。子会话own调用内重复携带父内容，其输入3000仍正常计入，并在来源视图指回父内容。

### E5：PTC

某模式5次模型调用均只暴露run_code，发生3次run_code调用，内部12次SDK子调用，其中8次read。

显示“入口调用3；SDK子调用12；read子调用份额8/12”。不得报告read曝光0导致覆盖无穷，也不得把3+12作为同类工具执行分母。SDK暴露清单无法可靠解析时其使用覆盖率unknown，但12次子调用仍是事实。

### E6：反馈不等于模式失败率

模式窗口100个可读会话。问题P共6条反馈涉及4个会话；其中两个会话重复反馈同一次发生。

显示“6条报告 / 4个受影响会话 / 本窗口已报告会话占比4%”；合并重复发生后另外展示发生实例数。不能说其余96%成功，不能自动说P由模式造成。没有历史版本的反馈关联modeId+unknown-version。

### E7：关键约束检查

原记录包含“交付后打开测试环境；只有用户要求跳过时例外”。摘要出现“测试环境”不等于保留了触发条件及动作；普通词集合不得计为完整保留。

只对有明确结构绑定的约束检查各槽位。未匹配标“未能确认保留”，给原文/摘要证据，允许用户判断同义改写。Doctor不启动环境、不判断Agent该不该被强制续写。

## 7. 第一轮已确认与第二轮样本细则

G1=A：默认估算token，保留观测总量与底层尺寸，见1.3。
G2：采用资源贡献加权与独立质量问题。

G4=B：允许轻量被动采集公开可得的必要快照，不调用模型、不执行工具、不主动探测；当前配置与实际Agent代际必须区分。
PTC 口径是数据事实约束；具体首版能力覆盖仍在最终范围评审时明确。

### 7.1 有效交互门槛（H2纠偏后）

H2=A已确认：门槛为至少四条有效交替消息，即两个完整用户—模型往返 `U1 → A1 → U2 → A2`，不是四个往返，也不按原始DSH turn/start数量直接判断。先合并纯继续恢复链，再判断两个往返是否成立。

取消/中断必须结合原因和恢复输入归并：中断后只有“继续”且无新增指令，应作为原交互恢复，不增加有效交互数量。若包含纠偏、改变要求或其他实质新增内容，则不是纯恢复。不能只用continue关键词匹配，例如“继续，但不要修改数据库”包含新约束。

J3已确认：纯规则仅合并明确恢复标记、严格继续短语及相邻边界支持的纯恢复。原因/语义不能可靠判断时按正常对话处理，不视为恢复，不因该歧义排除样本，不调用LLM给全部历史计轮。仍需实际有效模型回应才构成完整往返；数据缺失与回应未完成另列coverage，不当作恢复歧义的同一种情况。

门槛用于模式样本，不禁止单会话诊断。短会话反馈保存且可读，但不混入筛选后分母。J2=A：fork只计算本分支自身有效往返，继承历史不使短分支达标；原执行去重与后续真实携带计量继续有效。

### 7.2 版本有效性（H1已确认，替代时间窗口）

有效性由配置/内容版本决定，不按最近30天、归档时间或自然时间衰减。配置和相关内容未变，历史及归档样本仍属于同一有效版本；默认分析同版本全部可用历史。日期可作审计/用户显式筛选条件，但不是质量有效性的判据。

分析对象分别绑定自己的来源版本：组件内容指纹、模式权威配置版本、请求/上下文快照；不能仅因modeId相同就声称全部版本一致，也不能因为不同会话的普通聊天文本不同就把每个会话拆成不可聚合的模式版本。

报告更新与来源失效区分：同版本新增样本意味着统计可更新，不使旧样本失效；相关配置或内容变化使依赖它的旧结论需重算；无关来源变化不应全部重跑。分析规则/计量版本作为可复算元数据单列，不冒充用户配置变更。

历史版本不可恢复时保留unknown分组，可看模式ID级观察，不归入已证明同版本的统计。相同可见工具清单hash不足以证明完整预设相同。

归档不等于删除，正常纳入同版本候选。问题保存occurredAt/reportedAt及发生时版本；旧问题现在补录不成为当前版本的新实例。版本变更也不自动表示问题已修复，需新版本证据或用户判断。

### 7.3 更新后的算例

一年前归档的会话与今天会话有相同可证配置/内容版本：两者可参与该版本分析，不按年龄降权。

昨天会话使用旧配置V1，今天已改V2：V1结果仍能查看，不冒充V2结论。

同modeId历史版本未知：继续提供unknown组统计，不能以今天的配置反向填补。

一次用户请求被中断三次，每次只说“继续”：不据四次运行边界认定已经有四个有效往返；归并后按最终可证交互计数。

这些规则替换之前基于日期窗口和无条件计入中断轮的建议。H2=A两个完整有效往返；J2仅fork自有往返；J3无法确定为恢复则按正常对话，均已确认。

J6补充：C13等保留风险指标仅可用于用户主动请求的诊断，不作为每次compact的自动校验或门禁。压缩保护执行本身不运行这些指标、不触发额外模型评审或补发。
