## 2. 首版范围推荐

### 2.1 首版必须闭合的能力

- 无模型会话统计：C01–C06、C08、C10、C12、C14；条件缺数据明确partial，不编造精度。
- 工具/Skill/MCP：T01–T05、T07、PTC入口及子调用绝对量；S01–S04；M01/M03及可归属的M02。统一条件/分母契约，不能因指标属于基础就无条件输出比率。
- 模式侧：完整可得当前配置+活跃代际观测，历史modeId及unknown组，相关内容版本缓存和样本门槛；能力覆盖先基于模式目标、声明与可观测映射，不声称任意自然语言目标都可确定性证明。
- 用户反馈F01：创建/关联/补证据/撤回，Problem与Occurrence分离、实例去重、统计资格分离。
- 明确范围的语义健康/质量分析与纠偏提炼；非必要不调用，不全历史扫描。
- 约束增强作为首版可选能力交付：保护候选、原意审阅、确认及适用模式内的压缩保护。不能悄悄延期用户核心需求；若未批准provider变更，则需用户明确选替代范围，而不是团队自行删掉。
- 当前会话与模式两个视角，原文/配置/调用证据下钻，估算token主显示，独立质量问题。

### 2.2 首版条件性规则

C07近重复、C09前缀变化、C11结构引用、C13确认原子保留、T06工具混淆候选、S05 Skill重叠：给有证据的基础版本，不能声称全语义覆盖。未满足结构/校准条件的部分标未运行。相似工具问题在首版至少提供描述对照、轨迹证据及用户反馈关联，不仅用调用频率代替。

PTC SDK曝光解析无法可靠完成时只缺该比率，保留子调用事实；不是把PTC整个移出产品。

### 2.3 明确不纳入首版

S06泛化Skill遵循率、自动任务验证器、反事实回放、万能健康分、自动工具裁剪、自然语言通用冲突求解器、后台LLM监督、MCP主动探活、当前未发送草稿分析。模型建议不可自动执行配置修改或外部动作。

上述为完整推荐范围，第三轮用户确认后冻结；新增需求进入后续范围，不从第一批基础统计就宣称全部完成。

## 4. Given / When / Then 验收集（待开发实现为fixture）

### 量化与来源

- **AT01 加权可复算**：100k同单位文本，工具结果40k其中8k额外副本、Skill10k其中2k额外副本；结果重复贡献10%，不称质量下降10%。
- **AT02 不重计Skill**：Skill正文在tool结果里；用途视图属于Skill，角色视图属于tool，两者总量不相加。
- **AT03 观测与估算分开**：usage42.8k与估算44.1k；均保留标签，不缩放分项凑42.8k；output不进cache读比例分母。
- **AT04 小而重要**：短验收要求缺失同时大块重复；独立问题不被体积平均稀释。
- **AT05 表面重建**：替换仅覆盖中间区间，前后仍有效；不能只保留最新压缩后事件；缺投影支持标partial。
- **AT06 回退不等于误用**：A失败B成功；显示结构码/参数/序列，未知则unknown，不能确定判A错误。
- **AT07 曝光缺失**：20会话15曝光完整，工具可见10且调用4；覆盖4/10、观测15/20，缺失不算0。
- **AT08 PTC**：3次run_code内12次SDK调用read占8；份额8/12，不用8/15；未知SDK曝光不报0%覆盖。
- **AT09 Skill两条路径**：工具加载与用户手势分别记；手势未经历目录曝光时不塞同一漏斗。
- **AT10 Skill再加载**：压缩移除后重载不当驻留内重复；相同正文不同参数渲染不冒充源文件版本。
- **AT11 MCP**：长名无法逆映射及普通Error无结构码时保留unresolved；没有Prompts机制显示不适用，不自动ping。

### 模式、版本、有效交互

- **AT12 极简能力**：没有专用编辑工具但Shell覆盖基础文件操作，不机械判能力缺口；也不因仅一个工具就判100%健康。
- **AT13 版本不按日期**：同可证版本的归档旧会话和新会话均入组；最近但不同版本分别统计。新样本增加不使旧样本失效。
- **AT14 活跃代际**：模式已改V2而旧Agent仍绑定V1；各自指纹正确，当前列表不能覆盖旧运行配置。冷旧历史unknown不反填。
- **AT15 四条有效消息**：U1-A1-U2-A2达到门槛；一个往返加三个纯继续恢复不达标。
- **AT16 恢复含新增约束**：“继续，但不改数据库”不按纯继续合并；J3规定无法确认纯恢复时按正常对话，不因该歧义暂排除或调用模型分类。缺模型有效回应仍不能构成完整往返；fork只计本分支自身往返。
- **AT17 fork账本**：父输入1000+2000，子own3000；合并6000不9000。子own请求的继承内容照样算携带。
- **AT18 只读扫描**：跨会话扫描不走retain/follow、不启动冷Agent、不拿写锁。归档列表正常包含，页中错误显示覆盖缺口。
- **AT19 快照一致性**：扫描中新增事件或删除会话；报告固定截止边界，结果partial/可更新，不偷偷变分母。

### 反馈与用户控制

- **AT20 两步反馈**：从消息点记录，选类型保存；自动附来源，说明和纠正证据可后补，不强迫根因。
- **AT21 重复问题**：6条报告4个会话，多标签不重复算会话；撤回/合并可修正，未反馈不等于成功。
- **AT22 需求变化**：用户后来加需求引发追加工作；报告现象，不自动归因模式/Agent原先遗漏。
- **AT23 删除源**：归档不失效。J4=B：确认源会话删除后清除原文摘录及可还原原文的证据缓存，只保留问题类型、用户自填说明及已删除状态；不得再向UI/模型提供原文。临时不可读不误判删除；离线期间不承诺即时物理清理，恢复后优先同步并在核实前不提供缓存正文。

### 模型与约束增强

- **AT24 显式分析**：更新统计无模型；用户启动会话/模式分析只用计划范围和选定模型，不把模式全部session送给LLM，不自动回填task label。
- **AT25 纠偏原意**：本轮只设计不变成永远不开发；旧错误理解留证据但不等权注入；新增例外待用户确认。
- **AT26 配置授权**：未批准压缩provider替换时只提供候选/证据，不能改preset；允许后只改选择的模式并显示旧Agent仍旧版本。
- **AT27 输入集合去重**：同一确认ID/revision有多个证据来源，构造compact任务时仅提供一项，摘要任务包含融合而非重复表达的指令；不在输出后运行保留校验器。
- **AT28 未选部分已有**：原文明确留在未压缩后缀时，摘要任务说明无需再列一份；压缩后无额外补发。映射不明不伪造确定结论，不按输出匹配决定补入。
- **AT29 无事后验证**：摘要采用同义改写或未返回要求ID，Doctor不运行逐条保留检查、不新增judge、不因保留判定拒绝摘要或重试；界面只显示增强摘要执行状态。
- **AT30 普通并发控制**：要求被用户明确撤销时按操作取消/版本规则处理，宿主自身表面稳定性仍执行；不启动新语义验证流程。
- **AT31 宿主错误**：摘要不够小或被取消时沿用宿主正常失败语义，不绕过shrink门槛、不承诺pruner先前改动回滚；不存在额外“Doctor保护校验失败”。
- **AT32 不监工**：即使反馈说忘开测试环境，也无端口检查、steer、turn-stopping拦截或自动启动工具。
- **AT33 draft与观测**：被动观测仅公开已有事件/配置；不读取当前draft、不加载所有Skill、不主动外部探测。
- **AT34 预算取消**：超过准备计划预算先缩范围或请求显式扩额；取消不启动新调用，保留已知费用，来源变化不自动重付费。

### 兼容与生命周期

- **AT35 缺能力**：低版本/服务缺失/日志不支持只禁对应能力；不深导入私有src或修补宿主。
- **AT36 写入并发**：两页面编辑反馈/确认对象时expectedRevision冲突可见；幂等提交不生成重复发生。
- **AT37 崩溃与缓存**：缓存可重建，清缓存不删用户反馈；原子写失败不回成功；旧schema备份后迁移，未来schema只读。
- **AT38 Provider卸载**：恢复前检查配置revision；用户中途改配置则报冲突，不盲目覆盖。卸载不删除宿主日志、不无感重启旧Agent。

## 6. 设计收尾

J1–J5已确认：可选provider、分支自有门槛、不确定恢复按正常对话、证据随源删除、手动分析默认预算。

J6最终决定：保护约束只执行，不校验。撤销原A/B失败策略问题；通过输入组织、来源/版本管理、摘要指令和宿主正常事务支撑能力，不以逐次校验替代功能设计。AT27–31及W6已相应修订。

设计已定稿，不再增加保留校验、监工或默认模型评审。设计文档已有明确需求、接口、数据、算例、验收对应；实现阶段验证公开包兼容和工程正确性，不冒充设计期已完成运行测试。仍需用户明确开发指令才写实现。
